# 승인된 계산·집계

spec-v0.9 / domain-ir-v3의 명시적 계약을 실행한다. 고객별 업무 공식을 추정하지 않는다.

- 단위는 컬럼과 상수에 선언하고, 덧셈·뺄셈은 같은 단위, 곱셈·나눗셈은 단위 지수를 검사한다.
- 계산 단계마다 결과 정밀도·소수 자릿수·반올림(half_even, half_up, down)을 지정한다.
  `down`은 0 방향 절삭이다. 이진 부동소수를 사용하지 않으며 단계별 반올림 순서를 유지한다.
- null 전파/거절, 0분모 오류/0/null을 명시한다. 초과·비정상 숫자는 CALCULATION_ERROR다.
- 변경 명령의 계산은 모든 대상 행을 잠근 뒤, 쓰기 전에 한 번 계산한다. 이후 쓰기로
  값이 달라져도 계산 결과를 재평가하지 않는다. 계산 실패 시 명령 전체를 롤백한다.
- 집계는 한 승인 테이블의 count/sum/average/min/max와 그 결과를 참조하는 계산이다.
  count는 전체 행 수다. 다른 집계는 null 거절/무시 정책을 따른다. 유효 값 0개는
  명시한 빈 결과 정책(0/null/오류)을 따른다.
- date 기간의 시작·종료 포함 여부를 각각 명시한다. 역전된 기간은 오류다.
  시간대 있는 시각 집계·조인·그룹별 집계·캘린더·스케줄러는 별도 확장이다.
- 집계는 읽기 전용 REPEATABLE READ 스냅샷에서 실행한다. 명시한 최대 행 수를
  초과하면 RESULT_LIMIT_EXCEEDED로 거절하며 일부 행의 합계를 반환하지 않는다.
  최대 10,000행·문장 시간 5초·잠금 대기 2초이며 성능 보장을 의미하지 않는다.
- 읽기 API도 역할·세션·CSRF를 검사한다. 계정/조직별 행 접근 제한은 별도다.
  집계 값을 별도의 수정 API에 넘기는 것은 원자 거래가 아니며 저장 명령에서
  집계 결과에 의존한 동시성 정책을 자동 보장하지 않는다.

명세에 연결한 정상·경계·실패 API 시나리오를 검증한다. 업무 인수 및 고객 승인과
기술 검증은 별도다. 재실행은 최신 DB의 새 스냅샷이며 이전 집계 값을 재사용하지 않는다.
