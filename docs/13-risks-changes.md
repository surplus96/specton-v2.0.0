# 위험과 변경 관리

## 위험 관리

| 위험 | 영향 | 대응 |
|---|---|---|
| 계약 불일치 | 저장 상태·API·화면 해석 실패 | 호환성 테스트와 명시적 스키마 이전 |
| 검토 오탐·미탐 | 불필요한 재작업 또는 결함 승인 | 근거 검증, 고정 평가, 사용자 최종 확인 |
| 정답 누출 | 품질 과대 보고 | 개발·평가 입력 분리, 사전 해시 고정, 회귀 평가 구분 |
| 생성 SQL 위험 | 검증 DB 오염 | 허용 AST, 제한 계정, 롤백·정리 확인 |
| 문서 엔진 제약 | 추출 누락·PDF 잘림 | 지원 형식 명시, 한글·대형 표·ERD 실측 |
| 호출 시간·비용 초과 | 실행 실패 | 토큰·시간·재시도 상한 및 사용량 기록 |
| 외부 자료 이용 조건 | 배포 제약 | 출처·버전·이용 조건 보존 |
| 환경 차이 | 재현 불가 | 잠금 파일·이미지 고정·복구 점검 |
| 확장 범위 증가 | 핵심 기능 지연 | 수직 흐름별 완료 기준과 단계별 착수 조건 |

## 변경 요청

변경 전후, 근거, 영향받는 요구사항·계약·API·팩·TC, 대안, 결정, 재검증 결과를 기록한다. 로컬 문서나 연결된 원격 이슈를 사용한다.

계약 변경은 기존 저장 상태와 호출자를 분석하고, 필요한 이전·호환 기간·복구 방법을 함께 정한다. 설계 결정이 달라지면 새 ADR을 만들고 이전 결정을 대체 표시한다. 승인 산출물은 덮어쓰지 않고 새 버전으로 만든다.

확장의 위험·일정·검증 기준은 [개발 계획](planning/README.md)을 따른다.
