# 구현 범위와 제약

[![한국어](../assets/lang-ko.svg)](../ko/roadmap.md) [![English](../assets/lang-en.svg)](../en/roadmap.md)

이 문서는 현재 코드가 제공하는 동작과 실행 조건을 정의한다. 기능별 검증은 [테스트 안내](testing.md), 사용 순서는 [전체 처리 흐름](workflow.md)을 따른다.

## 지원 매트릭스

| 영역 | 구현된 동작 | 조건·제약 |
|---|---|---|
| 문서 분석·설계 | 요구 표 분석, 확인·검토·승인, 기능 명세·ERD·DDL·RTM | Excel·CSV·HWP·HWPX 표; PDF 입력·OCR 제외 |
| 도메인 해석 | 공통·재고·설비 팩, 승인 설계의 타입·키·관계 사용 | 용어팩 추가만으로 새 업무 연산이 구현되지는 않음 |
| 명세 도출 | 승인 설계에서 화면·API·저장 구조 연결, AI 보완, 준비도·납품 준비도 | 기본 구조는 검토 상태로 생성; 업무 정책·인수 기대값 확정 필요 |
| 범용 앱 생성 | 등록·조회·수정·상태 전이·필드 조건 | 지원 타입·키·매핑을 가진 승인 계약 |
| 원자 명령 | 여러 레코드의 조건·계산·쓰기, 전체 롤백·멱등 응답 | 선언한 DB 대상 내 단일 거래; 외부 부수 효과 제외 |
| 계산·집계 | Decimal·단위·반올림, 단일 테이블 필터·집계·계산 | 명시한 null·빈 결과·0분모·조회 상한 정책 |
| 자동 검증 | 소스 무결성, 설계 일치, SQL·HTTP·실행 API 인수·Chromium | 별도 작업자·Docker 필요; 자연어 인수는 자동 통과되지 않음 |
| 미리보기·채택 | 소유자 격리 미리보기, 후보 비교·채택 이력 | 검증 근거·비교 해시 검사; 운영 배포와 별개 |
| Gmail 변경 | API 수집·중복 억제, 영향 분석, 승인 후 후보 생성·재검증 | 기존 화면·권한·필드·명령·계산의 허용 변경; 일반 구조 변경 제외 |
| 설계 재생성 | 실행 명세와 기능·ERD·DDL·RTM의 일치 검증 | 원본 승인 보존; 구조가 같으면 ERD·DDL 내용 유지 |
| 데이터 이전 | 같은 저장 구조의 격리 이전·실패 복구 검사 | 임의 스키마/타입 변환·운영 전환 제외 |
| 고객 UI·인증 | 계약 기반 기본 화면, 고객 계정·서버 세션·API 역할 | 플랫폼 Google 로그인과 별도; 행 소유권·고객 SSO/MFA 제외 |
| 납품 | 독립 소스 ZIP, 파일 검사, DB 초기화·계정·운영 도구 | 설치·업무·복구에 대한 고객 환경 인수 필요 |

## 실행 환경 경계

`compose.deploy.yml`은 플랫폼 DB·API·웹을 구성한다. 피드백·생성 앱 검증 작업자는 별도 실행해야 한다. 로컬 통합 실행 도우미와 고객 ZIP을 제공하며 운영 작업자 배치·확장·관측·자동 배포는 현재 기본 Compose의 범위 밖이다.

생성 UI는 업무 계약을 확인할 수 있는 기능 화면이다. 별도 시각 명세를 해석해 브랜드·레이아웃·컴포넌트 디자인을 생성하는 기능은 포함하지 않는다. 일정 작업·외부 시스템 동작·테넌트별 행 격리도 추가 실행 계약이 필요한 영역이다.

## 상태 해석

| 상태 | 의미 |
|---|---|
| 설계 승인 | 해당 설계 revision을 사용자가 승인 |
| 명세 승인 | 실행 계약과 포함·유예 범위를 승인 |
| 검증 통과 | 해당 소스에서 실행한 검사에 대한 결과 확보 |
| 후보 채택 | 프로젝트 구현 기준을 해당 후보로 선택 |
| 업무 인수 | 포함한 고객 업무·운영 조건의 별도 확인 |

검증 보고서는 실행한 사례와 `not_run`·실패·유예 범위를 함께 표시한다. 자동 검증이나 후보 채택을 전체 업무 인수로 해석하지 않는다. 고객별 지원 가능성은 승인할 계약과 실제 실행 사례를 기준으로 판단한다.
