# 설계·생성·고객 변경 처리 흐름

[![한국어](../assets/lang-ko.svg)](../ko/workflow.md) [![English](../assets/lang-en.svg)](../en/workflow.md)

Specton의 처리 단위는 소유 프로젝트, 승인 설계, 실행 명세 버전, 구현 후보, 검증 결과다. 고객 변경은 새 버전과 후보를 생성하고 검토 후 프로젝트의 채택 기준을 갱신한다.

## 1. 요구사항 분석과 설계 승인

`내 프로젝트`에서 프로젝트를 만들고 문서를 등록한다. Excel·CSV·HWP·HWPX의 요구사항 표와 선택한 도메인 팩을 기반으로 분석한다. 추출·요구 해석 질문이 있으면 원문을 확인해 답변한다. 기능·엔티티·관계와 검토 지적을 확인한 뒤 최종 승인한다.

출력은 기능 명세서, ERD, DDL, RTM이다. 승인에는 실행 ID·revision·설계 모델·산출물 해시가 연결된다. 프로젝트에 해당 승인 실행을 연결하면 이후 명세의 설계 기준이 된다.

## 2. 실행 명세 도출과 업무 계약 검토

프로젝트의 실행 명세에서 승인된 테이블·열·키·관계를 화면·API·저장 매핑으로 연결한다. 구조 도출은 등록·조회·수정 초안을 생성하고 요구별 적용 상태를 `needs_review`로 남긴다. 이 시점에 고객 업무 전체가 구현됐다고 판정하지 않는다.

명세에서 다음 내용을 확정한다.

| 검토 대상 | 확인 내용 |
|---|---|
| 요구 범위 | 포함할 기능, 유예 사유, 원문 요구 연결 |
| 역할·API·화면 | 누가 어떤 작업을 호출하고 어떤 화면에서 사용하는지 |
| 업무 계약 | 상태 전이, 필드 조건, 다중 레코드 변경, 계산·집계 |
| 인수 사례 | 준비 데이터, 호출 순서, 성공 응답, 경계·실패 기대값 |
| 미해결 질문 | 원문으로 결정할 수 없는 규칙과 답변 |

AI 명세 보완은 검토용 제안을 만든다. 준비도와 납품 준비도 보고서에서 구조 연결, 실행 근거, 남은 인수 항목을 각각 확인한다. [실행 계약](business-contracts.md)을 보완한 뒤 최신 버전·해시로 명세를 승인한다.

## 3. 구현 후보 생성과 자동 검증

승인한 명세로 소스 ZIP을 생성한다. 패키지는 DB·API·고객 UI, 고객 계정 도구, 승인 명세, 원본·재생성 설계, 파일 manifest를 포함한다. 생성 자체로 검증 상태가 통과가 되지는 않는다.

격리 검증을 요청하면 별도 작업자가 소스·계약 일치를 검사하고 PostgreSQL·HTTP·브라우저 검사를 실행한다. 결과는 해당 후보의 소스 해시와 연결된다. 실행 인수 사례가 없는 자연어 조건은 `not_run`으로 남는다. 실패 시 보고서의 단계·오류·해당 요구를 확인하고 명세 수정부터 새 버전으로 진행한다.

## 4. 고객 앱 미리보기와 후보 채택

브라우저 검증을 통과한 소스로 격리 미리보기를 준비한다. 생성된 도메인의 화면에서 등록·조회·수정, 관계 선택, 명령·계산 결과를 직접 확인한다. 미리보기는 소유자 접근·만료를 적용하며 운영 서비스와 분리한다.

후보 비교 화면에서 변경 파일, 명세·설계 일치, 검증 결과, 요구별 미검증 항목을 확인한다. 현재 기준과 비교 해시가 일치하는 후보를 채택하면 프로젝트의 구현 기준이 갱신된다. 이 동작은 운영 배포를 실행하지 않는다.

## 5. Gmail 변경 요청 반영

채택한 기준이 있는 프로젝트에서 [Gmail 연결](gmail-feedback.md)을 진행한다. 검색 조건으로 수집한 메일에서 원문 요청을 인용해 변경 요청을 등록하고 AI 영향 분석을 실행한다.

기존 값과 제안, 직접·연관 영향, 질문을 검토한다. 명령·계산 변경은 모든 실행 인수 사례의 기대값을 사람이 검토한다. 검토한 변경안을 승인한 뒤 후보 생성·검증을 요청하면 새 명세 버전, 재생성 설계 문서, 구현 후보가 만들어진다.

자동 검증과 미리보기 후 기존 후보와 비교·채택한다. 채택 성공 시 변경 요청이 `applied` 상태가 된다. 명세·소스 생성 및 검증 등록이 실패하면 해당 DB 거래를 롤백하며 기존 채택 기준은 유지한다.

## 6. 고객 앱 납품

채택한 후보의 ZIP과 소스 해시를 기준으로 [설치·계정·백업/복구 절차](deployment.md)를 수행한다. 고객 앱은 별도 DB와 고객 계정을 사용한다. 같은 저장 구조의 격리 데이터 이전 검사와 실제 운영 이전은 구분한다.

최종 확인 대상은 설치, 역할별 접근, 포함 업무의 정상·실패 동작, 미검증·유예 항목, 백업 복구다. 자동 검증 결과와 고객 업무 인수 결과를 각각 관리한다.
