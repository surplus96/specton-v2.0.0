# 팩 자료의 출처와 정책 근거

[![한국어](../assets/lang-ko.svg)](../ko/domain-pack-sources.md) [![English](../assets/lang-en.svg)](../en/domain-pack-sources.md)

이 문서는 저장소에 포함된 자료와 구현 정책을 설명한다. 공식 표준 준수 인증이나 외부 제품 전체 구현을 주장하지 않는다. 공통 CSV의 배포 출처·판·파일 해시는 [sources.yaml](../../domain_packs/sources/sources.yaml), 재고 확장 어휘는 [lexicon_sources.yaml](../../domain_packs/inventory/lexicon_sources.yaml)이 기준이다.

## 공통 사전

공공데이터 공통표준 8차의 단어·도메인·용어 CSV를 고정 입력으로 사용한다. 원본 사본과 출처 고지를 유지한다. 생성기는 CSV의 인용 쉼표·인코딩을 처리하고 평가 문장에서 새 공식 단어나 약어를 만들지 않는다.

| 예시 | 사전 구분 |
|---|---|
| 일자 `YMD`, 일시 `DT` | 서로 다른 분류어 |
| 코드 `CD`, 명 `NM`, 번호 `NO` | 용어 끝에 쓰는 분류어 |
| 상태 `STTS`, 구분 `SE` | 수식어; 코드/명 등과 조합 |
| 수량 `QTY`, 금액 `AMT` | 정밀도·범위가 있는 숫자 도메인 |

분류어·단어 조합은 공식 데이터에 기반하지만 소문자 snake_case, 이름 길이 제한, 충돌 처리와 PK/FK 규칙은 프로젝트 구현 정책이다. 공식 근거와 프로젝트 선택을 혼동하지 않는다.

`strict`는 표준 도메인의 문자 날짜·Y/N·numeric 구조를 보존하고, `pg_native`는 명시적 매핑에 따라 DB 고유 타입을 선택한다. 실제 허용 타입·정밀도·규칙은 공통 YAML과 컴파일러를 따른다. 공식 이음동의어는 출처가 명확하고 모호하지 않은 매핑만 사용하며 원래 논리명과 진단 근거를 남긴다.

## 재고·설비 지식

재고의 공개 CSV는 포함/제외 이유와 해시가 있는 오프라인 어휘 근거다. 원본 바이트를 보존하며 공개 사전이 고객 업무 규칙을 확정하는 것은 아니다.

설비 팩은 설비 계층, 보전 계획·요청·작업·이력, 재고 연결 같은 CMMS 개념을 정리한다. 기존 조사에서 EN 13306의 보전 개념 구분과 ISO 14224의 고장 모드/원인 구분을 참고했지만 유료 표준 원문을 배포하지 않는다. 이 저장소가 해당 표준의 최신판 준수를 검증했다고 주장하지 않는다.

개발 예시의 승인 범위는 형식·출처·설계 지식이다. 평가 데이터와 정답은 팩에 넣지 않는다. 같은 작성자나 같은 AI가 본 자료의 결과는 독립 평가로 표시하지 않는다. 현장 일정·작업 정책·행별 권한은 고객 실행 명세에서 별도로 확정한다.

## 재배포와 갱신

프로젝트 코드는 [MIT](../../LICENSE), 로컬 제공 폰트는 [SIL OFL](../../frontend/public/fonts/OFL.txt)을 따른다. 데이터 출처 고지와 원본 manifest는 각각 유지한다. 판을 갱신할 때 출처·해시·변경 근거를 기록하고 팩 버전을 올린 뒤 재생성·회귀 검사한다. 과거 버전의 해시를 새 내용으로 대체하지 않는다.
