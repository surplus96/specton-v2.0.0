# 설계 결정 기준

[![한국어](../assets/lang-ko.svg)](../ko/decisions.md) [![English](../assets/lang-en.svg)](../en/decisions.md)

시스템의 계약·에이전트·저장·검증 경계에 대한 설계 근거다. ADR 번호는 코드의 참조와 연결되며 실제 요청·응답과 실행 형식은 API 스키마와 계약 모델을 따른다.

| 참조 | 주제 | 현재 기준 |
|---|---|---|
| ADR-0001 | 변경 검토 | 변경 목적·영향·검증 근거를 남긴다. |
| ADR-0002 | 제품 범위 | 문서 설계와 실행 앱/업무 인수를 구분한다. |
| ADR-0003 | 입력 계약 | 표 기반 입력과 원문 위치를 보존한다. |
| ADR-0004 | 문서 엔진 | HWP/HWPX 표, WeasyPrint·Mermaid PDF 출력; PDF 입력은 지원하지 않는다. |
| ADR-0005 | 웹 구성 | React·자체 CSS·React Flow를 사용한다. |
| ADR-0006 | 미정 우선순위 | 근거 없이 Must나 제외로 바꾸지 않는다. |
| ADR-0007 | LLM 실행 | 설정 가능한 모델·호출/토큰/시간 한도와 구조화 응답을 사용한다. |
| ADR-0008 | 관점 검토 | combined/parallel 전략과 관점 설정을 분리한다. |
| ADR-0009 | 계약·팩 | Pydantic·OpenAPI·팩 manifest/lock으로 경계를 고정한다. |
| ADR-0010 | 지적 심각도 | 자동 고칠 수 있는지와 중요도를 분리한다. |
| ADR-0011 | 인증·보존 | 세션·소유권·원문 접근 경계를 적용한다. |
| ADR-0012 | 실행기 | 체크포인트·DB lease로 재개·중복 처리를 관리한다. |
| ADR-0013 | 플랫폼 배포 | DB·API·웹 Compose와 같은 출처 프록시를 기본으로 한다. |
| ADR-0014 | 평가 | 개발 예시와 평가 정답을 분리하고 독립성을 과장하지 않는다. |
| ADR-0015 | 조건부 확인 | 추출/분석 확인은 조건부, 최종 승인은 명시적으로 한다. |
| ADR-0016 | 내부 ID·키 | 안정 내부 ID와 업무 키를 구분하고 키 없는 저장을 임의 확정하지 않는다. |
| ADR-0017 | DB 이전 | 기존 SQL 수정 대신 명시적 Alembic revision을 사용한다. |
| ADR-0018 | 소유 프로젝트 | Google 사용자, 실제 승인 실행, 프로젝트 기준을 연결한다. |
| ADR-0019 | 재고 정책 | 기존 재고 프로필도 승인 정책·멱등성·원장 근거를 따른다. |
| ADR-0020 | 검증 작업자 | 생성기와 분리된 신뢰 작업자가 소스/이미지 해시를 검증한다. |
| ADR-0021 | 미리보기 | 고정 브라우저 검증과 소유자 중계·만료를 적용한다. |
| ADR-0022 | 후보 채택 | 비교·검증·현재 기준 해시에 묶인 선택 이력을 남긴다. |
| ADR-0023 | Gmail 피드백 | 별도 읽기 동의, 원문 인용, 사용자 승인 후 재구현한다. |

## 실행 시스템의 설계 원칙

도메인별 하드코딩 대신 설계 기반 IR을 컴파일한다. 명령은 전체 롤백과 멱등 결과를, 계산은 정확한 수·단위·정밀도 정책을 갖는다. 요구별 실행 인수 기대값은 AI 제안과 분리해 검토한다. 변경 설계는 원본을 보존한 새 명세 버전으로 생성한다. 기본 고객 인증은 플랫폼 인증과 분리한다.

대형 명세의 AI 보완은 보호된 계약을 서버에 보존하고 제한된 변경만 병합한다. 데이터 이전은 지원하는 같은 구조의 격리 검증 범위로 한정한다. 상세 동작은 [아키텍처](architecture.md), [SDD](sdd.md), [피드백](gmail-feedback.md), [배포](deployment.md)를 따른다.
