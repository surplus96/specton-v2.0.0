# ADR-0023: Gmail 읽기 동의와 승인된 피드백 재구현

- 상태: 구현
- 날짜: 2026-11-15

## 배경

채택한 구현 기준을 고객 메일과 연결해 변경·검증·재채택하는 경로가 필요하다. 메일 수신이나 모델 출력만으로 실행 명세와 기준이 바뀌면 안 된다.

## 결정

Gmail API 읽기 권한을 로그인과 별도 동의로 요청하고 같은 Google subject에 연결한다. 갱신 토큰은 서버 키로 암호화하며 callback을 로그인 세션·PKCE·nonce·일회 state에 묶는다.

첫 수집 방식은 범위가 제한된 polling과 history 확인·재대조다. 외부 통신과 DB 게시를 분리하고 generation·작업 임대로 연결 해제/재설정/작업 중단 후 늦은 결과를 막는다. 모델 분석은 선택 원문·해당 명세의 외부 전송 동의와 호출 한도를 적용한다.

모델에는 실행 도구를 제공하지 않고 허용된 기존 필드 변경만 계약으로 받는다. 지원 밖 업무/DB 변경은 needs_input으로 남긴다. 사용자가 버전·해시에 묶인 변경안을 승인한 뒤 새 명세·소스·검증을 생성한다. 최종 후보 채택에서 분석 당시 기준을 다시 확인하고 변경 적용 이력을 함께 기록한다.

## 영향

메일→수정 화면→실제 검증→비교·채택의 제한된 흐름을 브라우저에서 검증할 수 있다. OAuth/Gmail/모델 응답을 합성한 검사와 실제 외부 계정 실증은 구분한다. Pub/Sub, 범용 구조 변경·운영 데이터 이전, 자동 보존·승인 산출물까지의 개인정보 삭제는 후속 범위다.

API·설정·인수 범위는 [구현 기록](../planning/16-gmail-feedback-implementation.md)과 [브라우저 안내](../planning/17-feedback-browser-guide.md)를 따른다.
