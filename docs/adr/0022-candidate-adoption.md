# ADR-0022: 비교 근거에 묶인 구현 후보 채택

- 상태: 구현
- 날짜: 2026-11-14

## 배경

생성 후보와 검증 보고서가 여러 개 생겨도 프로젝트의 현재 구현 기준을 결정할 방법이 없었다. 검토 이후 명세나 검증 결과가 바뀌는 경우 잘못된 후보를 기준으로 선택할 위험이 있다.

## 결정

프로젝트 소유자가 현재 채택 기준과 후보를 비교하고, 최신 설계·승인 명세 및 최근 브라우저 검증 근거를 확인한 뒤 명시적으로 채택한다. 비교 내용을 해시로 고정하고 채택 시 재계산한다. 현재 기준 ID의 compare-and-swap과 프로젝트 잠금으로 동시 채택을 직렬화한다.

채택을 별도 append-only 감사 테이블에 저장한다. 가장 큰 프로젝트 순서의 기록이 현재 기준이며 이전 기록 ID·해시를 보존한다. 요청 키와 본문 해시로 중복 기록 없이 네트워크 재시도를 지원한다. 동일 소스라도 새 검증 결과를 채택하면 새로운 근거 기록으로 남긴다.

업무 자연어 인수 조건의 미검증 상태를 명시적으로 확인받는다. 고정 시나리오 성공을 고객 인수 완료나 운영 배포 승인으로 해석하지 않는다.

## 영향

기존 명세·소스·검증·미리보기는 보존된다. 최신 설계/명세가 바뀌면 과거 후보를 그대로 채택할 수 없고 새 승인·생성·검증이 필요하다. 채택 기록의 해시는 일반적인 변조를 탐지하지만 DB 관리자에 대한 외부 서명 보증은 아니다.

세부 API, 상한, 운영 명령과 검증 범위는 [구현 문서](../planning/15-candidate-adoption-implementation.md)를 따른다.
