# ADR-0020: DB 큐와 별도 신뢰 검증 작업자

- 날짜: 2026-11-14
- 상태: 구현

## 배경

기존 격리 CLI는 결과를 플랫폼에 등록하지 않았다. API 서버가 Docker를 실행하거나 사용자가 제출한 JSON을 통과 증거로 받으면 실행 권한과 검증 신뢰 경계가 섞인다.

## 결정

PostgreSQL 큐와 별도 작업자를 사용한다. 요청은 최신 승인 소스 해시와 프로젝트 소유권에 묶는다. 작업자는 고정 검증기를 별도 프로세스로 실행하며 결과 해시·검증기·이미지·소스 해시를 대조한 뒤 DB에 등록한다. 외부 결과 업로드는 허용하지 않는다.

SKIP LOCKED와 소스별 활성 작업 유일 인덱스로 경쟁을 제어한다. 임대 토큰과 만료를 검사해 이전 작업자의 결과 등록을 차단한다. 취소 후 자원 정리를 확인해야 종료 상태가 된다. 중단 작업은 실행 상한과 유예 후 같은 Docker daemon에서 UUID 라벨 자원을 회수하고 실패/취소로 종료한다. 사용자 재요청으로만 새 실행을 만든다.

## 대안

| 대안 | 판단 |
|---|---|
| API 요청 안에서 Docker 실행 | 장시간 요청과 실행 권한이 API에 집중돼 제외 |
| 외부 보고서 업로드 | 실제 실행 출처를 신뢰할 수 없어 제외 |
| 별도 메시지 브로커 | 현재 단일 호스트 단계에는 운영 요소가 늘어나 후속 검토 |
| 임대 만료 즉시 재실행 | 이전 프로세스·자원과 겹칠 수 있어 회수 후 명시적 재요청 선택 |

## 결과

API 서버는 실행 권한 없이 작업 상태를 제공한다. DB HEAD는 0005_verification이다. 작업자 서비스 운영과 Docker 호스트 복구는 별도 책임이다. 검증 통과는 브라우저·업무 인수 또는 후보 채택을 의미하지 않는다. 상세 운영 절차는 [구현 기록](../planning/13-verification-worker-implementation.md)에 있다.
