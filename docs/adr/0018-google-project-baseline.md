# ADR-0018: Google 사용자 소유 프로젝트와 승인 설계 기준

- 날짜: 2026-11-14
- 상태: 구현, 실제 Google 계정 검증은 OAuth 클라이언트 설정 후 수행
- 관련: DEV-004·005, ADR-0011·0017

## 인증

사용자 선택에 따라 Google OpenID Connect를 사용한다. Google의 `sub`를 고유 계정 키로 쓰며 이메일 일치로 계정을 합치지 않는다. 이메일 변경은 같은 sub의 표시 정보만 갱신한다. [Google OIDC 공식 설명](https://developers.google.com/identity/openid-connect/openid-connect)의 authorization code 흐름을 따른다.

OAuth 요청은 브라우저 쿠키에 묶인 state, nonce, PKCE S256을 사용한다. 요청은 10분간 유효하고 코드 교환 전에 원자적으로 소비한다. ID 토큰은 라이브러리로 RS256 서명·issuer·audience·만료·발급 시각·필수 claim을 검사하고 nonce·azp·email_verified를 확인한다. Google access/refresh/ID token은 저장하거나 브라우저에 반환하지 않는다. Gmail scope도 요청하지 않는다.

플랫폼 세션은 서버 발급 난수다. DB에는 세션·CSRF 토큰의 SHA-256만 저장하며, 기본 30일 뒤 만료한다. 로그인하면 현재 브라우저의 이전 로그인 세션을 폐기한다. 로그아웃은 서버 세션을 폐기하고 관련 쿠키를 지운다. 외부 origin은 HTTPS와 Secure 쿠키를 요구하며 HTTP는 localhost/loopback 개발 환경에만 허용한다. 변경 API는 정확한 Origin과 세션에 결합된 CSRF 헤더를 요구한다.

## 소유권과 기존 실행

프로젝트 생성·조회·연결은 인증된 사용자 ID를 기준으로 검사한다. 소유자가 다르면 404이며 요청 본문의 owner/actor 값은 받지 않는다. 로그인한 사용자의 새 실행은 `user:<UUID>`를 owner_ref로 사용한다.

기존 익명 실행은 자동 이전하지 않는다. 사용자가 프로젝트 연결을 요청하고 기존 브라우저의 43자 난수 세션을 증명해야 한다. 계정 ID 문자열을 익명 쿠키로 넣어 다른 사용자의 실행을 가져올 수 없다. 실행 소유권 변경과 project_run 연결은 같은 트랜잭션으로 수행한다. 한 실행은 하나의 프로젝트에만 속한다. 기존 approval.actor_ref는 과거 승인 주체의 기록이므로 다시 쓰지 않는다.

## 실제 승인 기준 연결

완료된 현재 revision, 소유권, 프로젝트 연결을 먼저 확인한다. 이후 저장 스냅샷의 모델 해시, 같은 최종 승인에 결합된 기능 명세·ERD·DDL·RTM 및 manifest의 승인 근거, 저장소 안 실제 파일 바이트를 검사한다. manifest 자체의 approved 선언만으로 승인하지 않는다.

DDL은 해당 산출물에 결합된 통과 검증 시도와 파일·모델·검증기·정책·PostgreSQL 대상 버전이 모두 일치해야 한다. manifest의 run/revision/model_hash와 네 파일 목록도 확인한다. 경로 이탈·심볼릭 링크·없는 파일·승인 뒤 파일 변경은 거절한다.

기준 버전에는 프로젝트 내 순서, 승인 ID, 모델 해시, 파일 해시와 실행 revision을 보관한다. 같은 연결의 재요청은 기존 ID를 반환한다. 기준 버전 생성은 코드 생성 또는 실행 명세 승인과 별개다. 후속 생성기는 저장 파일을 다시 읽을 때 고정한 해시를 재검증해야 한다.

## 스키마와 범위

`0002_identity`는 사용자, 로그인 세션, OAuth 요청, 프로젝트, 실행 연결, 기준 버전 표를 추가한다. 기존 표의 데이터와 이전 설계 해시는 바꾸지 않는다. 명시적 upgrade는 기존 표와 신규 표의 실제 구조를 비교하며 파괴적 downgrade를 지원하지 않는다.

현재 프로젝트 목록은 최신 100개를 반환한다. 본격적인 대량 프로젝트 탐색의 cursor pagination, 계정 전체 세션 관리, 계정 탈퇴·보존 정책, 감사 이벤트 확장과 운영 로그인 유입 제한은 후속 운영 범위다. 안정 객체 ID·명세 질문/승인·생성기는 이후 DEV-006~008에서 연결한다.
