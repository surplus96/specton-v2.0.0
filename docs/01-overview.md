# 프로젝트 개요와 범위

Specton은 고객 요구사항 문서를 기능 명세서·ERD·DDL·RTM으로 변환하고, 규칙 및 LLM 검토와 사용자 승인을 거쳐 내보내는 설계 에이전트 서비스다. 이 저장소에서는 개인 유지보수와 후속 확장을 진행한다.

## 현재 제품

| 영역 | 구현 범위 |
|---|---|
| 입력 | Excel·CSV·HWP·HWPX. PDF 입력은 제외하며 PDF 출력은 지원 |
| 도메인 | 공통 표준과 재고·자재 팩, 설비 팩 |
| 설계 | A01 요구 분석, A02 기능, A03 엔티티·CRUD, A04 관계 |
| 검토 | 규칙 검사, A05~A08 관점 검토, A09 조건부 재작업 |
| 산출물 | 기능 명세서 Markdown·PDF, ERD Mermaid·PDF, DDL SQL, RTM Excel·CSV |
| 상태 | 체크포인트·실행 lease·revision·승인 근거·파일 해시 |
| 화면 | 실행 시작·진행·조건부 확인·최종 검토·결과·이력·AI Workspace |
| 운영 | FastAPI·React·PostgreSQL, Docker Compose·Caddy 배포 구성 |

PDF 생성은 실행 설정과 렌더링 의존성이 필요하다. 로컬 기본 설정은 비활성이며 배포 구성은 활성화한다. 실제 처리 흐름은 [아키텍처](03-architecture.md), 현재 코드와 문서 차이는 [프로젝트 분석](planning/00-project-analysis.md)에 있다.

## 처리 흐름

문서 입력 → 추출 확인 → 요구사항 분석·확인 → 기능·데이터 설계 → 모델 정리 → 산출물 생성·SQL 검증 → 규칙·LLM 검토 → 재작업 또는 최종 승인 → 다운로드.

추출·분석 확인은 조건부이고 최종 승인은 필수다. 승인한 revision의 파일 바이트와 검증 근거를 고정한다. SQL 검증은 DDL 실행 가능성 검사이며 실제 업무 시스템의 구현 완료를 뜻하지 않는다.

## 기존 완료 기준

대표 재고 입력에서 네 산출물, 원문 추적, 수정·재개, 승인 후 같은 파일 다운로드를 확인한다. 품질 지표는 평가 집합과 분모를 명시하고 실패·미실행·미완료를 보존한다. 기존 검증 기록은 [테스트와 평가](07-testing-eval.md), 재현 절차는 [인수 절차](23-acceptance-runbook.md)에 있다.

## 후속 확장

1. 품질 기준선·모듈 경계·성능·운영 안정성 개선.
2. 승인된 네 산출물과 실행 명세로 초기 DB·API·업무 UI를 생성하고 격리 환경에서 인수 테스트.
3. Gmail API로 고객 변경 요청을 수집하고 영향 분석·명세 개정·구현·재검증까지 연결.

상세 범위·우선순위·일정·수용 기준은 [개발 기획](planning/README.md)을 따른다. 이 단계에서는 기획을 작성하며 확장 기능의 구현 완료를 주장하지 않는다.
