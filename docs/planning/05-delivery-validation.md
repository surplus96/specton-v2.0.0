# 개발 일정과 검증 인수 기준

## 일정 가정

1인 전일 개발, 하루 순수 개발·검증 약 6시간, 주 5일을 기준으로 한다. 현재 코드 재사용과 재고 단일 템플릿이 전제이며 예상치는 약속된 납기가 아니다. 전체 68~96 작업일에 통합 여유 약 15%를 더해 약 16~23주로 잡는다. OAuth 외부 심사·도메인·격리 실행 인프라 준비 대기는 별도다.

주당 15시간이라면 같은 작업량은 전일 기준의 약 2배 기간이 필요하다. 첫 단계 측정과 실행 명세 스파이크 이후 남은 범위를 다시 산정한다.

## 테스트 층위

1. **단위·계약:** 명세 검증, ID·해시, 템플릿, trace, 메일 파싱, 상태·오류 전이. LLM·Gmail은 고정 응답으로 대체한다.
2. **DB 통합:** 실제 PostgreSQL에서 migration·동시 명령·행 잠금·권한·lease·outbox·승인 원자성.
3. **생성 앱 통합:** 격리 환경의 실제 HTTP와 DB를 사용해 업무 상태와 오류를 검증한다.
4. **브라우저 E2E:** 실제 UI→API→DB 경로, 권한·로딩·오류·다운로드·preview. Playwright와 고정 browser/image 버전으로 trace를 남긴다. [Playwright 공식 문서](https://playwright.dev/docs/intro)
5. **외부 실증:** 전용 테스트 Gmail에 합성 메일을 넣고 실제 OAuth·history·watch·재연결을 확인한다. 실제 LLM 실행은 별도 명세·비용 범위로 진행한다.
6. **부하·복구:** 기준 부하, 작업자 종료, 중복 작업, 일시 외부 장애, cursor 만료, 저장 중단을 주입한다.

현재 폴더에 없는 인수 원문·정답을 자동으로 복원하지 않는다. 재현 가능한 합성 시나리오를 새 버전으로 고정한다. mock 성공·단위 성공·실제 외부 연동 성공은 별도 열로 기록한다.

## 대표 인수 시연

초기 요구 문서 업로드 → 기존 네 산출물 승인 → 추가 규칙·화면 확인 → 명세 승인 → 생성 앱 기동 → 입고 10·출고 3·잔량 7 확인 → 동시 초과 출고 차단 → 메일의 확정 후 수정 제한·관리자 취소 요청 확인 → 영향 분석·승인 → 새 후보 생성 → 일반 사용자 거절·관리자 취소·원장·잔량 검증 → 전체 회귀 → 후보 채택 순서다.

시연에는 실패 흐름도 포함한다. stale 변경 요청 409, 중복 알림, 토큰 해제, 빌드 실패, 테스트 실패, 취소를 보여주고 마지막 성공으로 앞의 실패 기록을 덮지 않는다.

## 단계별 품질 기준

- 기능: 지원하는 재고 Must 사례 100% 통과. skip·미실행은 통과에 포함하지 않는다.
- 추적: 선택한 Must 요구의 100%에 유효한 구현·검증 근거가 존재한다. 삭제·제외는 사유와 승인 기록이 필요하다.
- 재현: 깨끗한 환경에서 같은 고정 템플릿·명세의 결정론 출력 해시가 일치한다.
- 변경: 기존 baseline·소스·검증 근거가 보존되고 새 후보의 채택만 현재 포인터를 바꾼다.
- 보안: 권한 우회·token 노출·작업 공간 이탈·미승인 실행을 차단하는 필수 테스트 통과.
- 복구: 실패를 설명하고 재시도 또는 중단할 수 있다. 미완료 작업을 완료로 표시하지 않는다.
- 성능: [품질 계획](01-quality-plan.md)의 측정 조건과 목표를 함께 보고한다.

## 비용과 자원

LLM 예상 비용은 단계별 입력·출력·캐시 토큰과 당시 실제 가격을 기록해 계산한다. `총비용 = 설계 + 명세 보완 + 구현 보완 + 검토 + 제한 재시도`이며 기존 문서 생성의 작은 시범 비용을 전체 SDD 비용으로 대입하지 않는다.

초기 기본 제안은 프로젝트 동시 구현 1개, 자동 수정 2회, 작업 20분, 토큰 상한과 일일 비용 한도를 설정값으로 두는 것이다. 실제 금액은 모델과 샘플 측정 후 확정한다. 큐 시작 전 예산을 예약하고 실제 사용 후 정산하며 사용량 미수신도 0원으로 처리하지 않는다.

별도 비용은 실행 VM·컨테이너·DB, 이미지/파일 저장, Gmail/PubSub 사용, OAuth 검증·보안 평가 가능 비용이다. 현재 운영 청구액·공급자 가격을 추정값으로 확정하지 않는다.

## 실제 착수 전 정할 항목

현재 계획의 기본안은 재고 도메인, 단일 생성 템플릿, Gmail 읽기 전용, 개인 개발자 소유 프로젝트, 운영 자동 배포 제외다. 인증 제공자, 격리 작업자 실행 위치, 외부 고객에게 공개할 범위, 메일 보존 조건, 호출 예산은 해당 단계의 스파이크에서 실제 환경과 함께 확정한다. 이 결정 전에도 DEV-001~003과 명세 계약 스파이크는 진행 가능하다.
