새 원격 저장소는 [surplus96/specton-personal](https://github.com/surplus96/specton-personal)이며 비공개 설정을 확인했다. 로컬과 원격 main 커밋 일치도 확인했다.

원본 파일 목록과 해시는 [소스 목록](source-inventory.json)에 있다. 이 값은 분리 출발점을 나타내며 새 저장소의 파일 해시와 혼동하지 않는다. 원본에 대한 단독 저작을 새로 주장하지 않는다.

## 정리한 범위

개발문서의 인명·계정 멘션·인력 배정·공동 승인 절차·이전 이슈 및 보드 연결을 제거하고 개인 개발 운영·검증 기준으로 바꾸었다. 기술 계약·제품 사용자의 HITL·실패와 미완료 기록은 유지한다.

- README 두 언어, CONTRIBUTING, CLAUDE, 개발문서·ADR·도메인 팩 설명을 정리했다.
- CODEOWNERS와 외부 보드·알림 스크립트/워크플로 5개를 제거하고 기존 CI는 유지했다.
- OpenAPI 설명의 이전 작업 참조를 제거하고 프런트 타입을 다시 생성했다. API 필드·타입은 유지했다.
- 서비스 소개 화면을 프로젝트 안내로 바꾸고 사용하지 않는 소개 스타일을 제거했다.
- 배포 Compose 프로젝트 이름을 `specton-personal-deploy`로 구분했다. 원본 배포 볼륨과 이름이 같지 않게 하며 이번 작업에서 컨테이너·운영 데이터는 변경하지 않았다.
- 저장소 내부의 새 개발 기획서를 허용하도록 기존 문서 검사에서 일반 명사만으로 차단하던 규칙을 좁혔다. 외부 문서 의존 검사와 관련 예제는 유지했다.

최상위 LICENSE와 폰트·외부 데이터의 라이선스·출처 고지는 보존했다. 업무 데이터의 조직 개념, 에이전트 관점 ID, 기존 실행 계약의 호환용 literal은 기술 의미를 유지한다. 승인 계약의 역할명 일반화는 Q-16의 별도 이전 범위다.

## 기존 평가 근거

`docs/evidence/`의 검토자 귀속·이전 작업 참조만 비식별화했다. 모든 JSON의 숫자·불리언·null 결과를 원본과 비교해 일치함을 확인했다. 진단 결과·통과/실패·분모·토큰·시간·가격 추정치를 새로 계산하거나 성공으로 바꾸지 않았다.

편집으로 JSON 파일의 바이트 해시는 달라질 수 있다. 기존 입력·모델·조건 해시는 그대로이며 비식별화된 파일 자체를 원본과 동일한 해시의 증거로 주장하지 않는다. 과거 실험 수치를 새 저장소에서 재실행한 성능으로 표시하지 않는다.

기본 pytest는 DB·실제 LLM 마커를 제외한다. skipped·deselected는 통과 수에 포함하지 않는다. 실제 LLM 호출, 별도 DB 통합 검사, 브라우저 수동 인수, Gmail OAuth·메일 수집, AWS 배포는 이번 작업에서 수행하지 않았다. 새 확장 기능은 기획 단계다.

설치 중 제한 네트워크에서 의존성 조회가 실패한 뒤 허용된 네트워크 접근으로 잠금 파일 기준 설치를 완료했다. 프런트 설치의 ESLint 지원 종료 안내와 Vitest의 localStorage 관련 런타임 경고는 검사 실패로 이어지지 않았다. 의존성 지원 상태 검토는 후속 품질 개선에 포함한다.

## 새 저장소 작업 방법

원본 폴더 대신 `specton-personal`을 작업 경로로 열고 [개발 규칙](../../CONTRIBUTING.md)을 따른다. 실행에는 별도의 `.env`와 필요 DB가 필요하다. 실행 포트는 기존 구성과 같으므로 원본 서비스와 동시에 띄우려면 포트와 접속 주소를 분리한다.

후속 구현의 출발 문서는 [개발 기획서](README.md)다. 다음 우선 작업은 기준선·CI·migration과 실행 명세 계약이며 실제 확장 구현을 이미 완료한 것으로 취급하지 않는다.
