# Gmail 고객 피드백과 승인 기반 재구현

2026-11-15. Gmail API 직접 연결, 수신함, 원문 인용 변경 요청, 외부 분석 동의, 제한된 명세 변경안 검토·승인, 새 소스·검증 작업과 최종 채택을 연결했다. 브라우저 테스트 절차는 [직접 테스트 안내](17-feedback-browser-guide.md)를 따른다.

## 구현 범위

| 단계 | 동작 |
|---|---|
| 연결 | 기존 Google 로그인과 별도 Gmail 읽기 동의, PKCE·nonce·세션 바인딩, 동일 Google subject 확인 |
| 토큰 | Fernet 암호화 refresh token, 서버 전용 교환·갱신, 연결 해제 시 로컬 폐기·Google revoke |
| 수집 | 수동/주기 작업, Gmail 검색 필터, 최대 500건 페이지 처리, history 확인·404 복구 |
| 수신함 | 제목·발신자·수신 시간·텍스트 본문, 첨부 메타데이터, 50건 커서 목록 |
| 변경 요청 | 채택된 프로젝트 기준 고정, 본문 부분 문자열 인용, 한 메일의 여러 요청을 별도 등록 |
| 분석 | 선택 인용·검토 설명·승인 명세의 외부 전송에 명시 동의, 구조화 출력, 직접/연결 대상·미확인 영향 표시 |
| 검토 | 변경 항목·대상·문구·기존 역할 선택, 추가 질문 답변, 버전·해시 기반 승인/반려 |
| 구현 | 승인 변경안을 새 실행 명세 버전으로 저장·승인하고 새 소스·검증 요청 생성 |
| 검증 | 기존 격리 DB/API/Chromium 작업자, 미리보기, 소스·명세 비교 사용 |
| 채택 | 분석 당시 채택 기준과 일치할 때만 새 후보 채택, 변경 요청 applied와 감사 사건을 함께 기록 |

자동 반영은 고정 생성기가 실제 사용하는 **기존 화면 이름·안내 문구, 기존 API 역할 권한**에 한정한다. 관련 유스케이스/화면 역할과 요구 설명은 함께 검토할 수 있지만 설명·역할 메타데이터만 바꾼 요청을 실행 기능 변경으로 인정하지 않는다. 운영 인증·화면 숨김 권한 체계 전체를 생성한 것으로 표시하지 않는다.

새 역할·엔티티·업무 명령·DB 스키마 변경은 unsupported 또는 needs_input으로 남긴다. 지원 밖 요청을 자연어 설명만 바꾸어 구현 완료로 처리하지 않는다. 기존 설계 네 산출물과 승인 소스는 보존된다. 운영 DB migration, 임의 코드의 3-way merge, 범용 자연어 인수 판정, 자동 수정 루프는 이번 브라우저 테스트 범위에 포함하지 않는다.

## 상태와 승인

변경 요청은 received → analysing → awaiting_decision → approved → validating → applied로 진행한다. questions/unsupported 또는 실행 변경 없음은 needs_input이다. 형식 오류·작업 중단은 failed로 남기며 외부 AI 분석은 자동 재시도하지 않는다.

검토 중인 제안은 원래 실행 명세를 수정하지 않는다. 저장한 제안의 해시, 요청 버전, 현재 채택 기준, 최신 설계·승인 명세를 확인한 뒤 명시적으로 승인한다. 승인 버튼은 저장되지 않은 화면 수정이 있으면 비활성화된다. 후보 생성 시 명세 수정·승인·소스 생성·검증 enqueue·변경 연결을 하나의 DB 트랜잭션으로 처리한다. 컴파일 실패 시 기존 명세 버전도 유지된다.

검증 통과만으로 applied가 되지 않는다. 실제 후보 채택 API가 변경의 base_adoption_id를 확인하고 채택과 applied를 함께 저장한다. 다른 후보가 먼저 채택되면 이전 변경 요청을 재사용해 우회할 수 없다. 최신 기준에서 요청을 다시 등록한다. 동일 구현 요청 재시도는 기존 후보를 반환한다.

feedback_revision은 각 분석/수동 검토 제안과 기준·해시를 버전별로 보존한다. 일반 수정 경로는 이전 제안을 덮어쓰지 않는다. 원문 삭제 요청은 보존된 검토 내용도 지우므로 외부 서명된 불변 감사 저장소로 해석하지 않는다.

## Gmail 수집과 복구

첫 릴리스는 **polling과 범위 내 재대조**다. Pub/Sub webhook은 아직 제공하지 않는다. 각 주기에 messages.list의 범위를 끝까지 읽고 이미 수집한 ID는 본문을 다시 가져오지 않는다. history.list도 페이지 끝까지 확인하며 history 만료 시 현재 검색 범위를 다시 조회하고 복구 여부를 작업 결과에 남긴다. 선택 범위를 벗어났거나 Gmail에서 삭제된 메일은 저장된 과거 근거로 유지하며 원문 삭제 기능으로 제거한다.

- 수집 필터는 앱의 처리 범위이며 OAuth 권한 자체를 특정 라벨·발신자로 제한하지 않는다.
- 초안은 제외한다. 500건 초과 범위는 cursor를 전진시키지 않고 gmail_filter_too_broad로 멈춘다. 필터를 좁힌 뒤 다시 요청한다.
- 본문 조회·파싱 중 일부가 실패하면 전체 cursor와 수집 결과를 원자적으로 보존한다. 부분 실패를 성공으로 버리지 않는다.
- profile historyId를 조회 전에 확보해 수집 중 도착한 변경을 다음 주기에 재확인한다. historyId는 문자열로 보관한다.
- 연결·메일 ID 고유 제약으로 중복 저장을 막고, 삭제 tombstone은 같은 메일의 재수집을 막는다.
- 429/5xx/네트워크 오류는 최대 5회, backoff·jitter·숫자 Retry-After를 반영한다. invalid_grant/401은 reauth_required로 전환한다.
- 연결당 활성 sync 작업은 하나다. 재연결·필터 변경·연결 해제 시 generation을 올리고 실행 중 결과 게시를 차단한다.
- 계정 변경/로그아웃/새 연결 요청과 경합한 OAuth callback은 기존 세션과 소비된 state 기록을 다시 확인한다. 연결 해제 중 교환된 응답이 연결을 되살리지 못한다.

연결 해제는 신규 수집을 중지하고 로컬 토큰을 지운다. Google revoke 실패는 화면에 별도 안내한다. Gmail 연결과 로그인에 같은 OAuth 클라이언트를 사용하므로 Google 측 권한 철회 영향은 해당 클라이언트의 다른 Google 권한에도 미칠 수 있다.

## 메일·분석 데이터

메일 HTML은 텍스트로 변환하며 script/style과 외부 이미지·링크 요청을 실행하지 않는다. 중첩 MIME/부품 수/본문 크기 상한을 적용한다. 첨부는 자동 다운로드·분석하지 않는다. 본문을 제공하지 않는 MIME은 빈 본문으로 표시하며 인용 요청 등록이 차단된다.

외부 모델에는 사용자가 선택한 인용, 추가 설명, 해당 승인 명세만 전송한다. 메일 계정 토큰, 원본 첨부, 다른 프로젝트 자료를 전달하지 않는다. 모델은 도구와 실행 권한이 없고 출력은 허용 필드·실제 객체 ID·원문 인용·SpecBundle으로 다시 검증한다. 모델 문장만으로 승인하거나 SQL·코드를 실행하지 않는다.

외부 분석은 서버 설정과 요청별 명시 동의를 모두 요구한다. 기본 사용자 한도는 24시간 10건, 호출당 출력 8,000토큰, 90초 timeout, API/구조화 자동 재시도 0회다. 명세 입력 크기도 제한한다. 실제 호출 모델·토큰·시간은 분석 근거에 저장한다. 추적되지 않은 영향은 unknown_impact이며 전체 고정 suite와 별도 업무 검토를 요구한다.

원문 삭제는 수집 본문·헤더·첨부 메타데이터·요청 인용·설명·분석/검토 사본을 지우고 진행 작업의 게시를 막는다. **이미 생성·승인한 명세·소스는 별도 이력으로 남는다.** 예약된 90일 자동 보존 정책, 백업 전체 삭제, 승인 산출물까지의 법적 삭제 워크플로는 별도 운영 작업이다.

## 저장·작업자

플랫폼 HEAD는 0008_feedback이다. 기존 0007 기록을 유지하면서 gmail_oauth, gmail_connection, feedback_message, feedback_change, feedback_job, feedback_event, feedback_revision을 추가한다.

작업 임대는 300초이며 게시 시 lease token·만료·입력 generation을 확인한다. Gmail 수집은 180초의 호출 루프 제한을 둔다. 외부 통신 중 DB 트랜잭션을 잡지 않는다. 만료된 sync는 시도 한도 내 재실행하고, 만료된 분석은 사용자에게 재시도를 맡겨 중복 과금 위험을 제한한다.

실행:

```bash
uv run python -m specton.persistence.migrate upgrade
uv run python -m specton.persistence.migrate check
uv run python -m specton.feedback.worker
```

피드백 작업자와 생성 앱 검증 작업자는 별개다. 검증·미리보기 작업자는 기존 runtime/postgres/browser 이미지 설정으로 실행한다. 로컬에서는 scripts/feedback_dev.py가 API·웹·두 작업자를 함께 관리한다.

## 검증 근거

[브라우저 종단 보고서](evidence/feedback-browser-report.json)는 실제 플랫폼 HTTP·DB와 생성 앱 Chromium을 사용했다. 외부 Google OAuth/Gmail 응답과 AI 응답은 합성 fixture다. 실제 사용자 Gmail 동의·수신 및 실제 모델 추론 성공으로 표시하지 않는다.

종단 경로: 수신 동기화 → 본문 인용 요청 → 외부 전송 동의 gate → 분석 → 저장 변경안 승인 → 새 후보 → 실제 검증 → 수정 화면의 격리 미리보기 → 비교·채택 → applied 확인. 스크린샷은 로컬 var/test-results/feedback-browser/에 보관한다.

## 최종 검증 결과

- Python 전체 2,232 통과·17 skip (232.55초). 최종 Gmail/API 계약 집중 22건 통과.
- DB 전체 408 통과 (956.81초). 최종 피드백 통합 7건도 통과 (50.63초).
- 실제 브라우저 종단 1건 통과 (63.32초). Google/Gmail/AI만 합성 응답이며 플랫폼 HTTP·DB·생성 앱 검증·격리 미리보기는 실제다.
- 프런트엔드 273 통과. ESLint·OpenAPI 생성 타입·TypeScript/Vite 빌드, Ruff/포맷, mypy 178개 모듈 통과.
- 로컬 개발 서비스의 /health 및 /feedback 응답 200, 미로그인 Gmail API 401을 확인했다. 실제 Google 동의와 사용자 메일·모델 호출은 사용자가 브라우저에서 확인할 단계다.
